01 / CASE STUDY

Contesto

Il progetto nasce per studiare un assistente tecnico specializzato in Python che possa recuperare conoscenza salvata, correzioni e codice validato. Non è presentato come un sistema autonomo capace di apprendere senza supervisione.

02 / CASE STUDY

La sfida

Gestire la conoscenza persistente e distinguerla dalle risposte del modello linguistico, mantenendo tracciabili le fonti recuperate e controllando errori, timeout e disponibilità del server LLM.

03 / CASE STUDY

La soluzione

Il backend espone API FastAPI con schemi Pydantic e persistenza SQLite/SQLAlchemy. Un ConversationService coordina riconoscimento dell'intento, ricerca nella memoria, costruzione del prompt, client LLM locale e composizione della risposta.

04 / CASE STUDY

Architettura

La documentazione M02 descrive il flusso FastAPI → ConversationService → MemoryService/PromptBuilder → LocalLLMClient → modello locale via LM Studio → ResponseComposer. Il sistema documentato lavora su singoli turni e non conserva implicitamente la cronologia della conversazione.

05 / CASE STUDY

Risultati e sviluppi

La documentazione tecnica indica M01 completata e M02 stabilizzata con test e una verifica di integrazione con LM Studio. La memoria semantica avanzata prevista per M03 è ancora una milestone futura, non una funzionalità già presente.
